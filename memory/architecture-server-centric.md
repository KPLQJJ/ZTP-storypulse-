# 作品管理架构：服务端为中心

**决策日期：2026-05-20**
**状态：已确定方向，待实现导入/导出增强**

## 核心原则

数据库是唯一真相源（Single Source of Truth），用户通过网页端创作和上传，支持一键下载最新版本到本地。不采用本地文件夹 + 云盘同步方案。

## 为什么不用本地同步方案（方案 B）

- 实现复杂度高 — 需要本地客户端、文件监听、增量同步、冲突解决
- 冲突处理是硬骨头 — CRDT/OT 太重，"最后写入胜出"体验差
- 与现有网页端架构割裂，相当于维护两条产品线
- 核心卖点是 AI 审稿，不是云盘

## 当前已有能力

- 网页端创作（简介编辑保存）
- 文件导入（.md/.txt 读取导入）
- 章节上传（支持 .txt/.md）

## 待增强（C 方案折中）

在服务端为中心的基础上增加导入/导出增强层：

- 本地文件夹批量导入 .md/.txt
- 一键导出整部作品为 ZIP/EPUB
- 不增加架构复杂度，覆盖本地 ↔ 云端流转需求

## 会员付费方向

付费点绑定核心审稿能力，不与通用云盘竞争：

- 审稿次数 / 模型质量等级
- 高级 Skill（分类 Skill）
- 导出格式（EPUB/PDF）
- 不在"云盘空间"维度竞争

## 与现有架构的关系

- `Novel` + `Chapter` 表不变
- `NovelDetailPage` 已有的编辑/导入功能为基础
- 审稿流程天然闭环：上传即就绪，AI 审稿直接读库
